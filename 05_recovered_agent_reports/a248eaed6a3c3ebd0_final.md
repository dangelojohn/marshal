## Report

**hermes-console** (qnap/hermes-console.git) — A standalone FastAPI + Vue3 agent control-plane, NOT an Odoo module. It runs as its own docker-compose stack (`hermes-api`, `hermes-ui`, optional `hermes-whatsapp`) fronted by Caddy/Cloudflare, and treats Odoo (Southbrook's `southbrook_hermes` addon) as one of several "tenant bridges" it pushes approved recommendations to via outbound HTTP/JSON-RPC (`api/tenant_bridges/southbrook_hermes.py`) — never the reverse. Core loop: `agent_loops.py` runs scheduled/triggerable loops (`platform_health`, `daily_digest`, `backup_health`, optional `lead_prospector` w/ Gemini grounded search) that ask an LLM for structured JSON recommendations, persist them to local SQLite (survives Odoo/QNAP restarts) in a `queue → approve/reject → apply` state machine, then push approved items through a bridge. It also runs a full **MCP server** (`api/mcp/`) exposing tools to Claude Code/Codex — read tools (Cloudflare, Home Assistant, Reolink, Phyn) and Phase-2 write tools (`hermes_file_recommendation`, `hermes_trigger_agent_loop`, `hermes_apply_recommendation`) that respect the same approve-gate. 30 test files under `api/tests/`, 48 commits, all within the last ~7 weeks, most recent commit 2026-06-17 (feat: Hub dashboard + MCP webmaster tools) — actively built and reasonably tested, described in its own README as "LIVE" architecture.

**Verdicts for a new event-services agentic platform:**
- **hermes-console: LIFT.** Its architecture is close to a direct fit for the ask (agent loops monitoring state → structured recommendations → human-approve queue → push to system-of-record via a bridge adapter). The `tenant_bridges/` pattern (implement one small adapter class per target system) is exactly the shape needed for "watch booth-setup status / scheduling board, raise attention items, draft exhibitor comms." The local-SQLite-first, Odoo-as-consumer design decouples the agent runtime from whatever event platform you build. Multi-provider LLM abstraction (`llm.py` ProviderRegistry) and the MCP tool server are reusable as-is.
- **odooai / ops: AVOID lifting as code** — pure environment snapshots with no orchestration logic; only worth skimming for QNAP deployment gotchas (README's "gotchas" table in ops is a decent quick reference) if you deploy on the same QNAP host.
