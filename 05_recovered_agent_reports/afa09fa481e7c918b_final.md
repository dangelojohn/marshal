## Governance Patterns Mined from southbrook-v19cr (all in `addons/southbrook_plm/`)

**1. Versioned specs** — `southbrook.cut.spec` (`models/southbrook_cut_spec.py`)
`version` (Integer) auto-increments only when one of 8 named `CONSTANT_FIELDS` actually changes value (compared per-record in `write()`, cut_spec.py:163-189) — bookkeeping edits (name/note/chatter) don't bump it. State machine `draft→active→superseded` with a hard single-active invariant (`_check_single_active`, :284). Full point-in-time reconstruction via `active_from`/`active_to` half-open interval `[from, to)` plus `predecessor_id`/`successor_id` doubly-linked chain, both stamped from **one shared `now`** in `action_activate()` (:480-514) so windows abut with zero gap/overlap. `_get_spec_active_at(when)` (:332) answers "what was live on date X" for warranty trace, with documented fallback semantics for pre-feature history. **Verdict: LIFT.** Maps directly to "event-package spec v3, active during booth-assignment window Q3."

**2. As-sold/as-ordered pinning** — `sale.order.line` (`models/sale_order_line.py`)
Two snapshot fields, `southbrook_cut_spec_version_id` (m2o, readonly, ondelete=restrict) and `southbrook_bom_version` (Integer), captured by `_capture_southbrook_version_snapshots()` at `action_confirm` (:113-158) — idempotent (`if line.southbrook_cut_spec_version_id: continue`). A later hardening closed a real gap: lines added to an **already-confirmed** order (change orders, upsells) never got stamped because `action_confirm` only fires once — fixed by also capturing in `create()` when `order_id.state in ('sale','done')` (:211-220), mirroring SAP's Order-BOM trigger-at-commitment logic. Deliberately **not** captured at draft/quote time — the comment explicitly reasons that pinning a quotation would be wrong the moment an ECO lands before acceptance. **Verdict: LIFT.** Maps to "booth/service-package spec frozen at contract signature, not at quote," including the create()-after-commit edge case for change orders.

**3. Four-eyes / dual approval** — `southbrook.eco.action_approve` / `action_apply` (`southbrook_eco.py`:1074-1194, 1500-1656)
Not a role-count check — an explicit identity comparison: `is_self_review = self.env.user.id in (eco.user_id.id, eco.create_uid.id)` blocks approval/apply by the ECO's own Responsible or creator unless `emergency_bypass` is set (:1150, :1604). Bypass requires a mandatory `bypass_reason` (`@api.constrains`, :231) and every arm/use posts a distinct chatter line (create-time arming logged separately from exercise-time use, :704-722, :946-955). RPC-hardened: setting `emergency_bypass`/`bypass_reason` is blocked in both `create()` and `write()` unless the caller holds `group_southbrook_plm_approver` (:686-698, :751-763) — closing the hole where the ACL (needed so users can author drafts) would otherwise let a plain user self-arm the bypass. Race-safe: `SELECT ... FOR UPDATE` + `invalidate_recordset` before the approve-decision check prevents two simultaneous approvers both stamping themselves (:1131-1137). **Verdict: LIFT.** Maps verbatim to "exhibitor booth change requires a second, non-requesting reviewer" with a logged break-glass for show-week emergencies.

**4. Immutable/append-only audit** — two distinct mechanisms, worth distinguishing:
- **Hard, code-enforced**: `southbrook.eco.write()` (:741-956) refuses any write to an applied/rejected ECO outside a narrow `_TERMINAL_WRITE_ALLOWLIST` (:735-739), gated by `_plm_lifecycle_authorised()`. That gate isn't a context-truthiness check but an **object-identity sentinel** (`plm_lifecycle.py`) — `PLM_LIFECYCLE = _PlmLifecycleToken()`, a `__slots__=()` singleton only importable in-process; guards use `is`, never `==`/truthiness, specifically because JSON-RPC can forge `{"context":{"plm_lifecycle": true}}` but cannot forge Python identity (plm_lifecycle.py:14-51). `@api.ondelete` blocks unlink of any non-open ECO (:1018-1035). **Verdict: LIFT** — the identity-sentinel technique is the single most portable piece of this whole codebase; use it anywhere "only my own state machine may authorize this write."
- **Soft, ACL-enforced**: `southbrook.qr.scan.log` (`southbrook_qr_kit/models/qr_scan_log.py`) has no write()/unlink() override at all — immutability comes purely from `ir.model.access.csv` (`perm_write=0, perm_unlink=0` for regular users; only `base.group_system` gets full CRUD, used by a time-boxed `autovacuum()` retention prune). **Verdict: PATTERN ONLY** — fine for a high-volume append log, but weaker than the ECO guard (a sudo() call anywhere bypasses it); don't reuse this shape where the immutability guarantee actually matters.

**5. ECO lifecycle** — `southbrook.eco` + `southbrook.eco.stage`/`southbrook.eco.type`
Configurable Kanban pipeline (`is_final`, `is_approved_stage`, `is_rejected_stage`, `approval_required` flags on `eco.stage`) decoupled from a fixed `state` enum (open/applied/rejected). `target_kind` (bom/cut_spec/rule/document) branches `action_apply`'s handler dispatch. Typed **effectivity** — immediate / scheduled-date (cron `_cron_apply_due_ecos` auto-applies once due) / use-up (human-confirmed stock exhaustion, no auto-apply) — treats "is it approved" and "when does it take effect" as orthogonal decisions (:288-459). Supersession via `action_create_superseding` (:1383-1498) rather than reopening history, with a guard against double-superseding and explicit stripping of stale description/attachments so a reviewer can't rubber-stamp against old evidence. Free-text `rejection_reason` (deliberately not a coded taxonomy — comment cites Arena/Windchill/CM2 precedent, :244-286). Cycle-time SLA metrics (`days_to_approve`/`days_to_apply`/`days_open`) plus a daily stale-ECO escalation cron. **Verdict: LIFT wholesale**, generalizing only the target_kind branch — "change order on exhibitor floor-plan after freeze" replaces "bom/cut_spec" with "booth-layout/service-package," everything else (stage pipeline, effectivity typing, supersession chain, SLA escalation) ports unchanged.

Tests confirming these mechanics: `southbrook_plm/tests/test_effectivity_pinning.py`, `test_eco_governance.py`, `test_eco_governance2.py`, `test_eco_workflow.py`, `test_w079_cut_spec_version.py`.
